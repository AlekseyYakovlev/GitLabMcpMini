## Phase Goal

**As a** автор агента AiAdventAgentV2, **I want to** через `gitlab-mcp.exe` вести Merge Request от просмотра до merge (список, детали, diff, комментарии, создание, правка, влитие), **so that** агент доводит свои изменения из Phase 2 до влитой ветки без ручной работы в GitLab.

<objective>
Fourth vertical slice: the agent talks on the MR (general comment, MR-06) and edits it (title, description, target branch, close/reopen, draft; MR-08). Together with Plan 03 this completes ROADMAP SC-3.

Purpose: the agent can respond to review, fix the title/target, close an abandoned MR, and take a Draft MR out of draft by sending a title without the prefix (the advice for detailed_merge_status=draft_status points here).
Output: create_merge_request_note in `mr_notes.go`, update_merge_request in `mr.go`, tests, 19-tool e2e/smoke.

Decision recorded for D-11 (flagged for the author): GitLab's Note response has no MR `web_url`. To stay closest to D-11 ("id заметки, web_url MR") the handler does ONE read `GetMergeRequest` before the POST. It supplies the MR `web_url`, and a missing MR fails as "не найдено (MR (iid) или проект)" before anything is written. The read comes before the write, so it is not a retry. Cost: one extra GET per comment.

Resolutions recorded (RESEARCH F2, Open Question 2, inside D-10): `UpdateMergeRequestOptions` has no draft field, so draft = title prefix. Un-drafting through `draft=false` stays unsupported (false = "not passed"). The agent un-drafts by sending `title` without the prefix, and the tool description says so.
</objective>
