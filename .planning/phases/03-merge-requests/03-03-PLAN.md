## Phase Goal

**As a** автор агента AiAdventAgentV2, **I want to** через `gitlab-mcp.exe` вести Merge Request от просмотра до merge (список, детали, diff, комментарии, создание, правка, влитие), **so that** агент доводит свои изменения из Phase 2 до влитой ветки без ручной работы в GitLab.

<objective>
Third vertical slice: the agent opens an MR from the branch it committed to in Phase 2 (MR-05). This is the first MR write, so it also brings the MR-aware write error layer: op keys for all four MR writes, status-aware write rules, and the "outcome unknown" extension from backlog 999.2 (D-15), which is closed in ROADMAP.md here. The Python smoke gets a loopback-only guard for writes so no future `--base-url` run can write to gitlab.com (backlog 999.5 concern; required before Phase 4).

Purpose: the agent's changes become reviewable; failures never produce silent empty or duplicate MRs.
Output: create_merge_request in `mr.go`, `mr_create_test.go`, extended `errors.go`, 17-tool e2e/smoke, ROADMAP 999.2 closed.

Resolutions recorded (RESEARCH, inside locked decisions):
- F2: no `draft` REST parameter; draft = title prefix "Draft: ".
- F4: GitLab silently creates an empty Draft MR for a branch without new commits, so D-09 "нет изменений между ветками" needs the compare pre-check (one extra read before the write; RESEARCH Open Question 3 accepted).
- F5: 409 duplicate carries "!N" in the message; fallback is one read-only list by source_branch.
</objective>
