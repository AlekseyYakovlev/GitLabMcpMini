## Phase Goal

**As a** автор агента AiAdventAgentV2, **I want to** через `gitlab-mcp.exe` вести Merge Request от просмотра до merge (список, детали, diff, комментарии, создание, правка, влитие), **so that** агент доводит свои изменения из Phase 2 до влитой ветки без ручной работы в GitLab.

<objective>
Second vertical slice: the agent reviews an MR, reading its diff page by page (MR-03) and its discussion (MR-04). Both reuse Phase 1-2 helpers unchanged (`renderDiffFiles`, `composeList`, `Budget`).

Purpose: review before merge; an empty patch must never be mistaken for "no changes" (ROADMAP SC-2).
Output: `mr_diff.go`, `mr_notes.go` (list only; `create_merge_request_note` is added to the same file in Plan 04), tests, 16-tool golden/e2e/smoke.

Resolution recorded (RESEARCH F1, stays inside D-06): GitLab's `/diffs` response has no `overflow` field; the "часть файлов не вернулась" line is derived from `changes_count` ending in "+" (GitLab caps it at "1000+"). Tests must NOT put an `overflow` key in fake `/diffs` JSON.
</objective>
