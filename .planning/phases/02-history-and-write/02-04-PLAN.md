## Phase Goal

**As a** автор агента AiAdventAgentV2, **I want to** через `gitlab-mcp.exe` просматривать ветки, историю коммитов и различия и вносить изменения в репозиторий (создать ветку, закоммитить один или несколько файлов), **so that** агент может не только читать код, но и готовить изменения для будущего Merge Request.

<objective>
Fourth vertical slice: the agent commits several file changes in one commit (`commit_files`, WRT-02, D-01..D-05) to a branch it created with `create_branch`, and sees the result (ROADMAP SC-3). Closes the STATE.md blocker "schema of nested actions[] must be accepted by client 1.30.x" with a golden snapshot and a real-client call.

Recorded deviation from RESEARCH (follows locked D-05 instead; RESEARCH Open Question 2 is marked RESOLVED accordingly): RESEARCH A1 proposed only commit-level totals because the create-commit response has no per-file stats. D-05 asks for per-file +/- and it is feasible without retrying the write: after a successful POST the handler makes ONE follow-up read, `fetchCommitDiff(new SHA, page 1, per_page 100)` from Plan 02, and counts +/- per file with `countPatchLines`. That GET is not a retry of the write (FND-07 intact). If the follow-up fails, or a file is too_large/collapsed or missing from the response, the commit is still reported as successful and that file line shows "+?/−?" (with a note pointing to get_commit when the GET failed).

Output: `schema.go`, `write.go` + tests, commit write rules in `errors.go`, golden `tools/list`, 11-tool e2e/smoke.

Scope note (checker WARNING 2): Task 1 is the largest task of the phase; it is kept whole because splitting would add a fourth task to this plan. The golden snapshot moved into Task 1 (it registers the tool), which makes Task 3 lighter.
</objective>
