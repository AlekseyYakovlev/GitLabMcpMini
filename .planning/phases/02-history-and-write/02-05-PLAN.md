## Phase Goal

**As a** автор агента AiAdventAgentV2, **I want to** через `gitlab-mcp.exe` просматривать ветки, историю коммитов и различия и вносить изменения в репозиторий (создать ветку, закоммитить один или несколько файлов), **so that** агент может не только читать код, но и готовить изменения для будущего Merge Request.

<objective>
Final vertical slice of Phase 2: the agent writes one file without choosing create vs update itself (`create_or_update_file`, WRT-03, D-06..D-09), protected against overwriting a concurrent change via `last_commit_id` (ROADMAP SC-4).

Recorded deviations from RESEARCH (follow locked D-08 "содержимое пишется как есть, ничего не меняется молча"; RESEARCH Open Question 3 is marked RESOLVED accordingly):
- RESEARCH A4 suggested skipping the POST when the new content equals the current one. Not adopted: the content is always sent as given; whatever GitLab answers (commit or error) is reported through the normal success/error path.
- RESEARCH Pattern 6 suggested refusing to overwrite a binary file. Not adopted (not in CONTEXT, would change behaviour silently); for a binary existing file the CRLF check is simply skipped, the text content is written as given.

Output: `create_or_update_file` in `write.go`, shared `decodeFileContent`, conflict rule in `errors.go`, regenerated golden (in Task 1, where the tool is registered), 12-tool e2e/smoke.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-21 | Tampering | lost update (overwriting a concurrent edit) | mitigate | last_commit_id from the GET on the same branch is sent with update (D-07); conflict mapped to "прочитайте его заново" |
| T-02-22 | Tampering | path argument | mitigate | NormalizeRepoPath rejects `..`; path goes through client-go escaping (GET) and JSON body (POST) |
| T-02-23 | Denial of service | large content | mitigate | validateCommitInput: ≤1 MiB, UTF-8 without NUL, before any request; 8 MiB response cap on the GET |
| T-02-24 | Repudiation / Tampering | duplicate write after ambiguous failure | mitigate | single POST via commitCore, never retried (test on 503), "Результат записи неизвестен" wording |
| T-02-25 | Tampering | silent content changes | mitigate | Content sent byte-for-byte (tests assert body equality); CRLF→LF change surfaced as a warning, never normalised (D-08) |
| T-02-26 | Elevation of privilege | writes to protected branches | accept | Enforced by GitLab; clear 400/403 guidance to create_branch + MR; read-only mode out of scope |
